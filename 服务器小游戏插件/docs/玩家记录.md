# 玩家记录（全服唯一文件）

> **一句话**：7 个小游戏的所有玩家记录（胜场/击杀/第一名/玩家名）现在只写在**一个文件**：
> `server/plugins/MiniGameLib/players.yml`。备份、换服、上传，只需要管这一个文件。
>
> 代码入口：`MiniGameLib/src/main/java/com/hub/data/PlayerStats.java`。
> 本文是这块的权威说明；改玩家记录相关代码前先读完本文（约 2 分钟，省掉读 6 个 Manager）。

## 1. 文件长什么样

```yaml
# 服务器唯一的玩家记录文件（战绩 / 击杀 / 玩家名）—— 由 MiniGameLib 统一读写。
games:
  duel:                      # 命名空间 = 插件
    wins:
      per-arena:             # 该插件原来的 data.yml 内容，原样搬进来
        test1:
          <uuid>: 4
      total:
        <uuid>: 8
  gtb:
    firsts:
      <uuid>: 4
  ...
version: 1
```

命名空间与结构（**全部改动前先看这张表**）：

| 命名空间 | 插件 | 键结构 | 游戏内查询 | 清空（OP） |
| --- | --- | --- | --- | --- |
| `duel` | DuelArena | `wins.per-arena.<场名>.<uuid>`、`wins.total.<uuid>` | `/duel stats [玩家]` | `/duel stats reset` |
| `gtb` | GuessTheBuild | `firsts.<uuid>` | `/gtb stats [玩家]` | `/gtb stats reset` |
| `hotpotato` | HotPotato | `firsts.<uuid>` | `/hp stats [玩家]` | `/hp stats reset` |
| `tntrun` | TntRun（雪塔大作战） | `firsts.<uuid>` | `/tr stats [玩家]` | `/tr stats reset` |
| `murdermystery` | MurderMystery | `wins.<uuid>`、`kills.<uuid>` | `/mm stats [玩家]` | `/mm stats reset` |
| `skypit` | SkyPit | `kills.<uuid>`、`names.<uuid>` | `/skypit stats [玩家]` | `/skypit stats reset [玩家]` |
| `football` | FootballArena（绿茵足球） | `wins.<uuid>`、`names.<uuid>` | `/fb stats [玩家]` | `/fb stats reset` |

## 2. 代码怎么用（加新小游戏照抄这 3 行）

```java
// 读：拿到"自己那一块"的独立视图（看不见别的插件），老 data.yml 只在首次自动迁移时用
data = PlayerStats.load("mysgame", new File(plugin.getDataFolder(), "data.yml"));

// 写：只替换自己那块，其它插件的内容原样保留
PlayerStats.save("mysgame", data);
```

要点：

- `data` 仍然是普通的 `YamlConfiguration`，**原来的 `data.getInt/set/getConfigurationSection` 一行都不用改**；
- `save()` 内部是「重新读盘 → 只替换自己那段 → 写临时文件 → 原子替换」，所以
  6 个插件轮流保存**不会互相覆盖**，写一半崩溃也不会把整个文件清空（替代了原来裸 `data.save(file)` 的写法）；
- 命名空间用**小写、无空格**的稳定 id（新建插件时自己起名，写进该插件 README 的速查卡）；
- 迁移用的 `legacyFile` 传 `new File(plugin.getDataFolder(), "data.yml")` 即可；没有旧数据的插件传 `null`。

## 3. 自动迁移（老服升级不会丢记录）

第一次加载时，如果 `players.yml` 里还没有自己的命名空间、而 `plugins/<插件>/data.yml` 存在且非空，
就把它整段迁进 `players.yml`，并打一行日志：

```
[MiniGameLib] 已迁移 data.yml -> players.yml [duel]：18 条记录（旧文件保留，之后不再读取）
```

- 旧 `data.yml` **不删**（保险），但**之后不再被读取**；确认无误可以自己删掉；
- 迁移只在「自己那段不存在」时发生，重复启动不会重复迁移、不会覆盖新数据；
- 面板服上传新 jar 后第一次启动会自动迁移**面板自己的** `data.yml` → `players.yml`，所以线上记录不会因为这次改造而丢失。

## 4. 备份 / 上传 / 恢复

| 场景 | 怎么做 |
| --- | --- |
| 打包上传（默认） | `pack-upload.ps1` 会先把 `players.yml` 快照到 `backups\players-<时间>.yml`，然后**把它排除在压缩包之外** —— 面板自己的玩家记录不会被覆盖 |
| 真的要把本地记录推到面板 | `pack-upload.ps1 -WithPlayers`（会覆盖面板记录，慎用） |
| 手动存档 | `powershell -ExecutionPolicy Bypass -File players-backup.ps1 -Action Save` |
| 看历史存档 | `players-backup.ps1 -Action List`（显示大小、时间、去重后的玩家数） |
| 把面板的记录拿回本地 | 把面板的 `players.yml` 下载到 `backups\`，然后 `players-backup.ps1 -Action Restore -File latest` |
| 恢复指定文件 | `players-backup.ps1 -Action Restore -File D:\path\players.yml` |

> `Restore` 在 `java.exe` 还在跑时会**拒绝执行**（运行中的服务端关服时会用内存里的旧数据回写，覆盖你的恢复结果）。
> 规则同上传：**先停服 → 再覆盖 → 再启动**。

## 5. 改完怎么验证

```powershell
# 1) 离线自检：迁移 + 合并写盘（不会碰 server\ 下的任何东西）
powershell -ExecutionPolicy Bypass -File D:\BuildBattle\check-stats.ps1
#    期望最后一行：[OK] player records: migration + merge-on-save verified

# 2) 起本地服，看启动日志（这就是"线上带对文件没有"的证据）
#    [MiniGameLib] 玩家记录 …\plugins\MiniGameLib\players.yml -> duel=3, gtb=5, hotpotato=3, ...
#    [MiniGameLib] 已迁移 data.yml -> players.yml [duel]：18 条记录（仅第一次）

# 3) 游戏里打一局，再 /duel stats 之类查一次；或直接看文件大小/时间变了没有
```

改动 `PlayerStats` 或任何插件的 `PlayerStats.load/save` 调用后，**必须**跑一次 `check-stats.ps1`：
它用真实的 `data.yml` 复现「迁移 → 改一块 → 其它块不丢 → 重新读到新值」的全过程。
（自检脚本会把 Java 源码生成到 `.build\statstest\`，产物在 `.build\statstest\run\plugins\MiniGameLib\players.yml`，可以打开看结构。）

## 6. 不要做的事

- ❌ 不要手改 `players.yml` 的层级（`games.<命名空间>` 是对外契约，改错等于把某个游戏的记录清空）；
- ❌ 不要让插件各自 `new File(plugin.getDataFolder(), "data.yml")` 再 `data.save(...)` —— 那就回到"6 个文件"的老路了；
- ❌ 不要在 `save()` 之外直接写 `players.yml`（会覆盖别人那块）；
- ❌ 不要为了"清理"删掉 `server/plugins/MiniGameLib/` 目录（记录就在里面）。
