# 已知坑 / 排查手册

> 用法：遇到"本地好、上传就坏"或"某个游戏不对劲"，**先在这里按症状搜一遍，再改代码**。
> 项目地图与命令见 `docs/开发须知.md`；玩家记录见 `docs/玩家记录.md`。
> 每条都是真踩过的坑，修法已经写进代码；不要凭直觉改回去。

## 1. 通用铁律（先看这 4 条）

1. **同优先级事件拦截必须限定自己的世界。**
   Bukkit 在**同一优先级**下按"插件注册顺序"调用监听器，而注册顺序取决于插件 jar 的读取顺序 ——
   **Windows 本地和 Linux 面板不一样**，于是会出现"本地好好的、传上去就坏"的诡异现象。
   > 真实事故：建筑猜猜乐（GTB）的爆炸保护原本无条件取消**所有世界**的 `EntityExplodeEvent`，
   > 而单挑（Duel）也在 HIGHEST 上放行风弹爆炸 → 谁后注册谁赢 → 本地能击飞、面板不能。
   ```java
   @EventHandler(priority = EventPriority.HIGHEST)
   public void onExplode(EntityExplodeEvent event) {
       if (!inArenaWorld(event.getLocation())) return;   // 不是我的世界 → 不插手
       ...
   }
   ```
2. **先停服 → 再覆盖 → 再启动。** 上传面板时顺序错了，或者只传 `plugins/*.jar`、
   漏了 `config/` 与各插件的数据文件，就会出现"传了没生效"。
3. **`MurderMystery / SkyPit / TntRun / DuelArena / HotPotato` 在 `onDisable` 里 `saveAll()`**，
   把内存状态回写到配置文件。**运行中上传** = 关服时被旧实例的旧内存覆盖（GTB 不写）。
   打包脚本 `pack-upload.ps1` 检测到 `java.exe` 还在跑会直接拒绝打包。
4. **必须一起传的清单**（`pack-upload.ps1` 就是按这个打的）：

   ```
   plugins/                 jar + 各插件数据（config.yml / data.yml / words.yml / arena-*.snap）
                            + plugins/MiniGameLib/players.yml（唯一玩家记录，默认排除出压缩包，见 docs/玩家记录.md）
   config/                  paper-global.yml + paper-world-defaults.yml  ★最容易漏
   server.jar  server.properties  bukkit.yml  spigot.yml  eula.txt
   cache/ versions/ libraries/   ★Paper 的下载缓存（mojang_26.2.jar 60,894,273 B / paper-26.2.jar 29,266,357 B /
                                 103 个库 78.8 MB，合计约 169 MB）。不带就只能靠面板自己重新下载
                                 （启动打印 `Downloading mojang_26.2.jar` + `Applying patches`）。
   world/                   只在改过地图/存档时才传
   ```

   另外有几处"状态不在 plugins 里"，排查"本地行、面板不行"时要想到：
   世界存档里的 gamerule（`pvp` / `mob-griefing`）、各世界的 `paper-world.yml`、
   以及计分板队伍（`allowFriendlyFire=false` 的队伍会让爆炸不推人）。

## 2. 症状 → 根因

| 症状 | 根因 | 怎么确认 / 怎么修 |
| --- | --- | --- |
| 本地好、上传面板就坏（同一份代码） | 同优先级事件拦截没限定世界，调用顺序在 Windows/Linux 不同（见 §1.1） | 搜该插件的 `@EventHandler`，看有没有"先判断是不是我的世界" |
| 上传了配置但没生效 | ① 服务器在运行中上传（被关服回写覆盖，见 §1.3）；② 压缩包多了一层 `server/`（解压后跑的还是旧文件）；③ 改的不是服务器实际读的那份 | `verify.ps1` 会打印真实路径、检查有没有嵌套 `server/`；打包后比对 jar 字节大小 |
| 某个游戏"没有场地/装备是旧的" | 面板的插件数据目录不是本地那份（漏传 / 旧文件） | 比对 `server\plugins\<插件>\` 下文件的大小与时间（`pack-upload.ps1` 会打印清单） |
| 面板/新服启动先打印 `Downloading mojang_26.2.jar` + `Applying patches`（要重新下 ~169 MB） | 上传包漏了 Paper 的下载缓存 `cache\` / `versions\` / `libraries\`（bootstrap 首次启动才生成，见 §1.4） | 确认：本地 `server\logs\server.log` 前 3 行就是这个场景（2026-09-20 首启）；面板上比对 `cache/mojang_26.2.jar` = 60,894,273 B。修：`pack-upload.ps1` 默认已带上这三个目录，带上了就直接从 `Starting org.bukkit.craftbukkit.Main` 开始 |
| 爆炸不推人（风弹 / TNT） | ① 有插件在 HIGHEST 取消了爆炸（见 §1.1）；② Paper `config/paper-world-defaults.yml` → `environment.disable-explosion-knockback`（只对玩家生效）；③ 玩家在 `allowFriendlyFire=false` 的计分板队伍里（`Player#ignoreExplosion` → `canHarmPlayer`） | 先看 `verify.ps1` 的 `disable-explosion-knockback=false` 那一行，再查队伍 |
| 世界规则不对（pvp 等） | 世界 gamerule 存在**世界存档**里；GameWorlds 每次启动按 `GameWorlds/config.yml` 重新套用 | 单挑世界必须 `pvp: true`；启动日志（实测中文）`[GameWorlds] 世界 world_duel 就绪：pvp=true 难度=NORMAL 怪物=false` |
| 玩家**进服就刷"你不在任何场中"**（几行 = 注册了 lobby handler 的游戏插件数） | `HubCore` 进服 / 右键"回主城"道具会调 `teleportToLobby` → `HubAPI.notifyLobbyHandlers`，把"复原大厅状态"广播给每个游戏插件；游戏插件的 `leave()` 在玩家本来不在场中时还各喊一句提示 | **lobby handler 只清自己的状态，用 `leave(p, true)` 静默版**（不在场中就直接返回，不打提示，也不要再调 `HubAPI.teleportToLobby` —— 回主城由 HubCore 负责，重复调还会再触发一轮广播）。玩家主动 `/xx leave`、右键退出床仍保留提示。已修：TntRun / HotPotato / MurderMystery |
| 主城菜单点了没反应 / 改的格子跟游戏里看到的不一致 | 菜单内容现在由 OP 编辑、存在 `config.yml` 的 `menu` 段（`/hub menu edit`） | 改完要 `/hub reload` 或重开菜单；`menu.items` 被删空会按 `games` 段重新生成默认布局 |
| 选场地菜单里羊毛颜色/名字不对 | 场地羊毛按各插件 `HubAPI.setArena` 上报的实时状态渲染：**绿=没人（WAITING 且 0 人）/ 黄=等待中（有人没开局）/ 红=游戏中（PLAYING）**，物品名就是场地名 | 介绍用 `/hub arena desc <游戏> <场地> <介绍…>` 写（存 `menu.arena-desc`，跟 `menu.sub` 分开，`/hub menu reset` 不会清掉）；OP 若给该场地写死了 lore，则以 OP 的 lore 为准（介绍不显示）。**颜色不对先查上报的 `players` 数**：0 人报 PLAYING 会显示成红 |
| 重载后菜单又变回默认 | `menu.items` 是空 section 时会被当成"没编辑过"触发默认生成 | 想留空白布局就至少留一个装饰物品（`action: none`） |
| `/hub menu action` 一直提示"写法：…"（照着帮助里的 `cmd:<命令>` 写却报错） | 参数解析按空格分词，`args[0]` 必须是裸类型名；`cmd:gtb` 会被当成未知类型 | 已修：类型尾部允许带一个冒号（`cmd:X` 与 `cmd X` 都认）。**排查同类问题的办法：在隔离测试服里插一行日志打印 `args`，别靠读代码猜** |
| 菜单动作里的游戏名点了没反应 | 动作里的游戏名要和 `games` 段 `name`（或自动发现的插件显示名）完全一致 | 启动日志那行「已登记 N 个游戏：…」就是权威名单（例如是 `SkyPit`，不是"天坑"）；`/hub games` 也能看 |
| 选场地菜单点进去一个物品都没有（看不到羊毛） | **点进去时的游戏名和场地状态存的键不一样**。场地状态是 `HubManager.setArena` 按注册表显示名（`canonicalName`）存的，而菜单动作里 OP 手写的名字可能少个空格或用 alias（真实案例：`action: game:单挑PvP` vs 显示名 `单挑 PvP`）→ `arenasOf` 查空表 → 子菜单空白 | 已修：`HubManager.arenasOf/arenaInfo` 查表前一律 `canonicalName`，动作在写入/点击时也归一化。**排查手法：`/hub games` 看权威显示名，再 grep 配置里的 `action:` 对不对得上** |
| 选场地菜单里点场地羊毛提示"正在游戏中"、但场地明明是空的 | 同上，游戏名对不上导致查不到场地 | 已修（同上） |
| 主菜单点某个游戏，弹出一个**一块羊毛都没有**的场地子菜单（那块地上明明有场） | 场地是**运行中新建成/刚圈好地**的，游戏插件没重新上报 → `HubManager.arenaInfos` 里没有这个游戏 → `arenasOf` 空表 → `clickGame` 判定"场地数 ≠ 1"于是打开子菜单（真实案例 2026-10-16：`/hp create 群系`+`/hp save` 后点「烫手山芋」，日志 `已为「烫手山芋」生成 0 个场地子菜单槽位`） | 已修 HotPotato（`saveAll()` 末尾 `reportAllArenas()` 重新上报）。**排查手法：grep 日志 `生成 \d+ 个场地子菜单`，出现 `0 个` 就是上报缺失**；临时绕过 = 先 `/hp join <场>` 再 `/hp leave`。TntRun/GTB/Duel/SkyPit/MM 的"运行中建场"未逐一确认 |
| **玩别的游戏**时后台报 `Could not pass event PlayerMoveEvent to MurderMystery` / `… to HotPotato`，异常是 `IllegalArgumentException: Cannot measure distance between minecraft:overworld and minecraft:world_tr`（真实案例：**雪塔大作战一局结束的瞬间**成对出现） | 那个游戏在**自己的 `PlayerMoveEvent` 里**把玩家跨世界传回主城（TntRun：`checkFade → eliminate → endGame → HubAPI.teleportToLobby`），注册顺序在它**之后**的监听器拿 `p.getLocation()`（已在新世界）去和 `event.getFrom()`（还在旧世界）比距离 → Bukkit `Location#distanceSquared` 跨世界直接抛异常 | 已修：MM/HP 的 `onMove` 比距离前先比世界（`!p.getWorld().equals(event.getFrom().getWorld())` 就 return）。**排查手法：读异常里的两个世界名 → 找出谁在那个事件里传送**；只比较 `getFrom()/getTo()` 的插件（Duel/SkyPit）不会中招 |
| 玩家记录/战绩"不见了" | ① 记录现在在 `plugins/MiniGameLib/players.yml`，看错了旧的 `data.yml`；② 上传时用 `-WithPlayers` 把面板记录覆盖了；③ 恢复备份时服务器还在跑（关服又被覆盖） | 看启动日志 `[MiniGameLib] 玩家记录 …players.yml -> duel=3, gtb=5, …`；改完跑 `check-stats.ps1`；详见 `docs/玩家记录.md` |
| **非 OP 的建筑者在「你建我跑」建造阶段挖不动方块**（放下方块正常，OP 正常；真实案例 2026-10-17） | GuessTheBuild 的 `GameListener#onBreak` 在 **NORMAL** 优先级上对**任何非 OP 且不在 GTB 局内**的玩家无条件 `setCancelled(true)`，**不分世界、不分场地**（GTB 的场地世界 `world_gtb` 正好也是 BuildRun 的场地世界）；BuildRun 原来的 `onBreak` 也在 NORMAL，同优先级谁先谁后不确定，GTB 的取消永远赢 | 已修 BuildRun：它的 `onBreak` 改挂 `HIGHEST`，对「建造阶段 + 自己的复制场地内」显式 `setCancelled(false)`（`BuildRunManager#canBuildBlockNow`），其它地方仍由 GTB 兜底。**排查手法：`javap -v` 看 jar 里每个 `onBreak` 的 `EventHandler(priority=…)`，谁在更高优先级上调用 `setCancelled` 谁说了算**。注意 GTB 这条世界级保护是主城/其它世界目前唯一的地基保护，别直接删。**2026-10-25 一掘到底也中招**（场地在 GameWorlds 新建的自定义世界，GTB 照样拦；OP 免疫）→ DigToBottom 1.0.2 同样在 HIGHEST 对「自己柱子内 + 对局中」显式 `setCancelled(false)` |
| **非 OP 玩家在某个区域挖不动任何方块（方解石/诡异菌柄等），OP 能挖**（先看上面 GTB 那条；自定义世界也中招就是 GTB，不是这条） | **原版出生点保护**：`server.properties` 的 `spawn-protection`（默认 16）只在 **respawn 世界（通常是主世界）** 出生点 `max(|dx|,|dz|) <= 半径` 的范围内、且玩家不是 OP 时生效；检查在 `ServerPlayerGameMode.handleBlockBreakAction` 里、**`BlockBreakEvent` 之前**（`javap -c` 已确认），被拦时连事件都不发出，插件既收不到也取消不了。**自定义世界（GameWorlds 新建的）不受这条保护**——那种情况请查 GTB | 修：`spawn-protection=0` 后重启，或把场地建到**自定义世界/远离出生点**。确认：`/dig debug` 会打印 `spawn-protection`、respawn-world、目标方块距出生点的 `max(|dx|,|dz|)`、是否受保护；启动日志也会警告「场 X 的圆心离出生点太近」。**别再往权限节点上查：DigToBottom 挖方块不看任何权限** |
| **时长/数值类配置"本地改了、面板不变"**（真实案例 2026-10-18：BuildRun 建造 180s，面板还是 120s） | 插件就是按 `config.yml` 读（`cfg("键", 默认)`），**文件里是旧值就是旧值**：面板那份文件没换（或覆盖落到了子目录）、面板跑的是旧 jar 生成的旧文件、或者运行中用旧 jar 覆盖配置 → 停服那一刻旧实例把整份配置（旧值）写回 | 看启动日志这两行：`[BuildRun] 时长：建造阶段 ?s…` + `配置：<绝对路径>（<字节> B，最后修改 <时间>）；build-seconds 取自 config.yml`。**修改时间不是刚才** → 覆盖没落到这个路径；**值还是 120** → 文件里就是 120。修：停服 → 覆盖 jar **和** `plugins/BuildRun/config.yml` → 启动（jar 已是"只重写 arenas 段"，不会再把 180 写回成 120） |
| **打包上传的地图里带着天坑击杀榜浮窗实体**（解包 zip，`world/dimensions/minecraft/overworld/entities/*.mca` 里 zlib 解压后能搜到 `text_display`；真实案例 2026-10-17：`r.0.-1.mca` 榜单区块） | **Paper 26.2 的 `Entity.setPersistent(false)` 对区块实体存盘无效**：`persist` 字段全 jar 只有 `ServerPlayer.saveParentVehicle`（玩家坐骑跟随存档）在读，Moonrise 的存盘只看 `shouldBeSaved()`（不查 persist）→ 插件生成的浮窗在每次自动存盘 / 区块卸载时都会写进世界（烟测 2 轮实证：复用分支执行了、实体照样进存档） | 修：`config/paper-world-defaults.yml` → `chunks.entity-per-chunk-save-limit.text_display: 0`（javap 证实语义：`-1`=不限，`0`=该类型每区块全部跳过，按类型跳过、不影响同区块其他实体；**存量实体**在下次该区块实体存盘时被空写洗掉）。排查手法：`javap -c` 读 `ChunkEntitySlices.saveEntityChunk0` 与 `Entity.shouldBeSaved`。**副作用**：summon/命令放置的 text_display 也不会再存盘（重启会消失，目前无人用） |

| **死亡后地上没有掉落、人还被直接送回主城**（真实案例 2026-10-18「幸运之柱最后一个死的人」） | ① 世界 gamerule `keepInventory=true`（GameWorlds 默认就是 true）：26.2 的 `ServerPlayer#die` 在 `PlayerDeathEvent` **之前**按 gamerule 就算好了掉落表，`setKeepInventory(false)` 只会把背包清空 → 地上什么都没有；② 别的游戏的 `PlayerRespawnEvent` 监听器没限定世界，`HubAPI.teleportToLobby` 还会 `notifyLobbyHandlers` → 触发本局 `leave()`，把 game 状态和旁观一起清掉 | ① `GameWorlds/config.yml` 里该世界加 `keep-inventory: false`（`verify.ps1` 已查 `world_lp`）；② 已修 DuelArena 的重生兜底（只在单挑世界生效）。**排查手法：grep 所有 `PlayerRespawnEvent` 监听器看有没有世界/场地判定，再看 GameWorlds 配置和 `/gamerule keepInventory`** |

## 3. 硬性约定（写代码前必读）

1. **`.ps1` 必须是纯 ASCII**（PS 5.1 无 BOM 时按 ANSI 读，中文注释会直接导致语法错误）。
2. **YAML 的 `键: 值` 冒号后必须有空格**：`detective-stone-seconds:90` 会让整份配置加载失败
   （Bukkit 给插件一个空配置 → 表现为"场地全没了"）。`verify.ps1` 会检查。
3. `gamehub:` 命名空间**不要改名**（写在各插件 kit 存档的物品数据里）。
4. 插件数据目录 = `server/plugins/<插件名>/`；源码里的 `src/main/resources/config.yml` 只是模板，
   **改配置要连线上那份一起改**。
5. 关服会 `saveAll()` 回写配置的插件：`MurderMystery / SkyPit / TntRun / DuelArena / HotPotato`（GTB 不写）。

## 4. 排查协议（省 token 的关键）

1. **先要证据，再改代码。** 一句日志、一段配置、一个文件大小，胜过我猜三轮。
   游戏里能直接拿到证据的例子：`/paper version`、`/gw list`、`/team list`、`/plugins`、
   控制台日志行、`/hub games`（显示名权威名单）。
2. **不确定的机制，去服务器 jar 里读字节码**（`javap -c`），别凭记忆：
   `ServerLevel.isPvpAllowed()` 读的是 gamerule；`WindCharge.explode()` 先看 `ExplosionPrimeEvent`；
   `ServerExplosion` 里的 `disableExplosionKnockback` 只对玩家生效。
3. **找不到原因就加一行诊断日志**（临时 jar，只打日志不改功能），一次就能定位
   （例：Duel 曾用过的 `[风弹诊断]` 已删；下次定位完同样记得删）。
4. **超过两轮没定位到，就换成"要证据"**，不要继续猜。
