# 小游戏插件接入指南

> 适用版本：HubCore 1.0.0 + MiniGameLib 1.0.0（Paper 26.x / Java 21+）。
> 阅读对象：各小游戏插件（建筑猜猜乐 / 单挑 PvP / 烫手山芋 / TNT Run / 密室杀手 / 天坑）的维护者。

---

## 一、三个角色

| 插件 | 职责 |
| --- | --- |
| **MiniGameLib**（公共库） | 提供 `com.hub.api.HubAPI`（主城对接）、`Chat`（消息）、`SetupMode`（建场模式）、`WaitCountdown`（等待倒计时）。**不注册命令、不碰玩法。** |
| **HubCore**（主城） | 大厅、中央菜单、统一 tab、小游戏插件发现；实现 HubAPI 需要的 `HubService`。 |
| 各小游戏插件 | 编译期只依赖 MiniGameLib；运行期还需要 HubCore 在服上。 |

HubCore 启动时会做三件事：

1. **扫描读取所有小游戏插件** —— 遍历 `plugins/` 目录下每个 jar 的 `plugin.yml`，凡是带
   `minigame-game: true`（或存在 `minigame:` 配置段）的插件，自动登记为一个"游戏"，显示在 tab 上；
2. **tab 按游戏分区** —— 头部（Header）分成 大厅 / 每个游戏，显示人数与名单；
3. **玩家前缀标注状态** —— `[等待中]`（在等待室）、`[已加入]`（对局中）、无前缀（在大厅）。

管理命令（OP 或 `hub.admin`）：`/hub reload`、`/hub games`、`/hub menu`、`/hub set`、`/hub item`、`/hub lock`。

## 二、接入三步

### 第 1 步：plugin.yml 加依赖与标记

```yaml
depend: [MiniGameLib, HubCore]     # 保证加载顺序
softdepend: [GameWorlds]           # 可选：多世界由 GameWorlds 托管

# ===== 给 HubCore 的标记（不影响原插件功能）=====
minigame-game: true
minigame:
  name: 建筑猜猜乐      # tab 分区显示名（建议用中文）
  icon: GRASS_BLOCK    # 可选，中央菜单图标（物品英文名）
  color: '6'           # 可选，tab 分区标题颜色，0-9 a-f
```

说明：

- `minigame-game: true` 是"我是小游戏插件"的开关；只写 `minigame:` 段也能被识别。
- 标记键名是**中性**的，不会因为主城插件改名而失效（历史键名 `gamehub-game` / `gamehub:` 已废弃）。
- 如果这个插件是闭源 jar，用 7-Zip 打开 jar 改里面的 `plugin.yml` 再保存即可，不用重新编译。

### 第 2 步：编译期依赖 MiniGameLib

```xml
<dependency>
    <groupId>com.hub</groupId>
    <artifactId>minigame-lib</artifactId>
    <version>1.0.0</version>
    <scope>provided</scope>
</dependency>
```

或用 `build.ps1` 统一编译（推荐）：

```powershell
.\build.ps1              # 编译全部插件到 .build\out\
.\build.ps1 -Deploy      # 编译并复制到 server\plugins\
.\build.ps1 -Only TntRun # 只编某个插件（自动带上 MiniGameLib + HubCore）
```

`HubAPI` 的包名仍是 `com.hub.api`，所以原来调用 HubAPI 的代码**一行都不用改**。

### 第 3 步：在正确时机调用 API

```java
import com.hub.api.HubAPI;
import com.hub.api.GameState;

// ① 玩家进入等待室 / 排队：
HubAPI.setGame(player.getUniqueId(), "建筑猜猜乐");      // tab 显示 [等待中·建筑猜猜乐]

// ② 游戏正式开始：
HubAPI.setPlaying(player.getUniqueId(), "建筑猜猜乐");   // tab 显示 [已加入·建筑猜猜乐]

// ③ 场地状态变化（中央菜单里该游戏的场地子菜单：绿羊毛=没人 / 黄羊毛=等待中 / 红羊毛=游戏中）：
HubAPI.setArena("建筑猜猜乐", "糖果屋", GameState.WAITING, 0, null);   // 没人 → 绿
HubAPI.setArena("建筑猜猜乐", "糖果屋", GameState.WAITING, 3, null);   // 有人等 → 黄
HubAPI.setArena("建筑猜猜乐", "糖果屋", GameState.PLAYING, 8, "第 3/8 轮"); // 游戏中 → 红
HubAPI.removeArena("建筑猜猜乐", "糖果屋");               // 场地被删除时

// ④ 游戏结束 / 玩家中途退出：
HubAPI.clearGame(player.getUniqueId());
HubAPI.teleportToLobby(player);                          // 可选：送回主城

// ⑤ 玩家成功加入等待室/进入场地时，全服公屏播报一条加入提示：
HubAPI.announceJoin(plugin.getName(), player.getName());
//   第一个参数传插件名（plugin.getName()）或游戏显示名都行，主城会查注册表归一化成显示名并套用它的颜色，
//   最终播报形如：[密室杀手] SharpOwO 加入了游戏

// ⑤b 游戏有多个场地（玩家必须知道加的是哪个场）时，多传一个场地名：
HubAPI.announceJoin(plugin.getName(), player.getName(), arena.getName());
//   最终播报形如：[单挑 PvP][重锤] SharpOwO 加入了游戏（场名固定金色，空/空白 = 与上面两参数版完全一致）

// ⑥ 对局内按队伍给 tab 名字染色（如绿茵足球红/蓝队；不传或传 null 恢复默认）：
HubAPI.setTabNameColor(player.getUniqueId(), "c");   // 红（蓝队用 "9"）
//   tab 的"游戏分区名单"和"玩家列表名"的名字段会变成该颜色，[等待中·…]/[已加入·…] 前缀不变；
//   玩家 clearGame（退出游戏/下线）时主城自动清除覆盖，不用手动还原。
```

规则与提示：

- **名字必须一致**：`minigame.name`（或 HubCore `config.yml` 里的 `alias`）要和这里传入的字符串一致，
  否则会按传入的原始名字单独分一个区。
- **传 `plugin.getName()` 时，本插件 `plugin.yml` 必须有 `minigame-game: true` 或 `minigame:` 段**：
  注册表靠它建"插件名 → 显示名"的映射（`GameRegistry`）。少了这段，`announceJoin(plugin.getName(), …)`
  查不到游戏，兜底直接用插件名，公屏就变成英文的 `[DuelArena]` / `[HotPotato]`（2026-10-16 的真实案例）。
- **不要**在 `PlayerQuitEvent` 里调 `clearGame` —— 玩家退出服务器时 HubCore 会自动清理。
- 玩家右键「回主城」道具或 `/hub` 时，HubCore 会回调各插件注册的 lobby handler，
  让插件把玩家踢出自身游戏状态（有防递归保护）：

  ```java
  HubAPI.registerLobbyHandler(p -> manager.leave(p));
  ```
- HubCore 没装/没启用时，以上调用**全部是空操作**，不会抛异常。

## 三、公共库还提供了什么

- **`com.hub.util.Chat`**：`send` / `broadcast` / `title` / `actionBar` / `color` / `toLegacy`，
  颜色统一用 `&`（也认 `§`）。需要给自己消息加前缀的插件，写一个很薄的本地包装类调用它即可。
- **`com.hub.util.SetupMode`**：OP 建场模式（备份背包/护甲/模式/位置 → 发带 PDC 标记的工具 →
  按工具 id 回调 → 退出还原）。公共部分（进场/退场、`save`、`exit`）在库里；
  插件专属工具（单挑的 kit GUI、建筑猜猜乐的选区木棍）通过 `Tool` + `Handler` 自己扩展。
- **`com.hub.util.WaitCountdown`**：等待室自动开局倒计时，规则与四个插件原来逐字一致：
  队列里有 OP → 暂停自动倒计时；人数 < min → 取消；≥ max → 3 秒；否则 30 秒；
  已在跑的 30 秒倒计时在满员时缩短为 3 秒；加人/退人都不重置。

详细 API 与迁移步骤见 [MiniGameLib/MIGRATION.md](../MiniGameLib/MIGRATION.md)。

## 四、HubCore 侧的配套配置

想让游戏出现在**中央菜单（右键指南针）**里，需要在 HubCore 的 `config.yml` 的 `games` 段有对应条目
（提供显示名、tab 颜色、加入命令），再把它摆进 `menu.items`：

```yaml
games:
  - icon: GRASS_BLOCK
    name: 建筑猜猜乐
    alias: 猜猜乐          # 游戏插件调 API 时传入的名字；不一致会导致多分区
    color: '6'
    command: gtb join      # game: 动作在没有任何场地信息时的兜底命令
    join-prefix: gtb join  # 加入指定场地的命令前缀（拼成 "gtb join <场地名>"）
```

菜单内容本身是 `menu` 段（**不用手写，OP 在游戏里编辑**）：

```yaml
menu:
  rows: 6
  title: '&e游戏大厅'
  items:
    '13':
      material: DIAMOND_SWORD
      name: '&c单挑 PvP'
      lore: ['&7点击进入']
      action: 'game:单挑 PvP'     # 只有 1 个场地就直接进，2 个及以上打开场地子菜单
  sub:                            # 每个游戏的场地子菜单（多个场地时点图标进入）
    单挑 PvP:
      rows: 3
      title: '&e单挑 PvP 场地'
      items:
        风场:                      # 键 = 场地名；也可用数字键当纯装饰槽位
          material: DIAMOND_SWORD   # 省略材质 = 按状态用羊毛：绿=没人 / 黄=等待中 / 红=游戏中
          lore: ['{state} {players} 人 {extra}']
  arena-desc:                     # 场地介绍（OP 用 /hub arena desc 写，不用手改）
    单挑 PvP:
      风场: '&7风很大，小心被吹下去'
```

**OP 编辑方式**：`/hub menu edit`（主菜单）/ `/hub menu edit <游戏>`（该游戏的场地子菜单），
在 GUI 里左键放下物品移动位置、右键复制（**动作一起复制**）、SHIFT+左键改材质、SHIFT+右键改名字、
双击改 lore（用 `|` 分行）、`Q` 删除；也可以走命令：
`/hub menu set|move|name|lore|action|del|rows|title|reset`（完整用法 `/hub menu help`）。
动作参数**用空格分隔**（带冒号的写法也认）：

```
/hub menu action 20 cmd gtb join          以玩家身份执行 gtb join
/hub menu action 20 game TNT Run          只有 1 个场地就直接进，多个场地开子菜单
/hub menu action 20 arena 单挑 PvP 风场    直接进指定场地
/hub menu action 20 none                  纯装饰
```

场地介绍（选场地菜单里那块羊毛的提示）单独一条命令，不用碰菜单布局：

```
/hub arena desc 单挑 PvP 风场 &7风很大，小心被吹下去|&7场地很小
/hub arena desc 单挑 PvP 风场 clear        # 清除
```

所有修改**立即写回 config.yml**，不用重启。

其他可调项：

```yaml
menu-item: COMPASS         # 大厅菜单道具
menu-item-slot: 4          # 菜单道具放在物品栏第几格（被主菜单占住时会自动顺延）
tab:
  show-empty-games: true   # true = 所有游戏分区常驻显示（含 0 人）
lock-inventory: false      # 大厅是否禁止捡/丢/移动物品
```

改完执行 `/hub reload` 即可生效，不用重启服务器。

## 五、常见问题排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| tab 里没有某个游戏分区 | 插件没加 `minigame-game` 标记 / 插件被禁用 / 没人在玩且 `show-empty-games: false` | 加标记；`/hub reload`；`/hub games` 确认是否登记 |
| 玩家一直显示"等待中" | 插件只调了 `setGame`，没在开局时调 `setPlaying` | 在游戏开始处补 `HubAPI.setPlaying` |
| 同一个游戏出现两个分区 | 插件传的名字与登记名不一致 | 在 HubCore 配置的该条目里加 `alias` 指向插件实际传入的名字，或改插件调用名 |
| 公屏加入播报显示成英文插件名（如 `[DuelArena]`） | 该插件 `plugin.yml` 没有 `minigame-game` / `minigame:` 段，注册表里没有"插件名 → 游戏"的映射 | 给该插件 `plugin.yml` 补 `minigame-game: true` + `minigame.name`（与 HubCore 配置的 `name` 一致），重编重传它的 jar |
| 状态错乱（回主城还是"已加入"） | 游戏结束没有调 `clearGame` | 在游戏结束/退出逻辑补 `HubAPI.clearGame` |
| 游戏里点"回主城"道具，退出后装备没还 | 插件没注册 lobby handler | 在 onEnable 补 `HubAPI.registerLobbyHandler(...)` |
| 报 `NoClassDefFoundError: com/hub/api/HubAPI` | MiniGameLib.jar 没装，或 `depend` 没写全 | 确认 `plugins/MiniGameLib.jar` 存在且 `depend: [MiniGameLib, HubCore]` |
